# Milestone 07 — Advanced Analytics & Monitoring

## What changed

Milestone 07 builds on the persisted Postfix lifecycle events and event store introduced earlier.

### Mail analytics in the admin dashboard

- Added `GET /api/analytics/mail?days=7|30|90`, restricted to owner/admin roles.
- Daily series includes queued, accepted, deferred, bounced and SMTP-rejected events.
- Summary separates internal and external accepted deliveries based on configured domains.
- Top recipient domains are aggregated; mailbox addresses and message content are not returned by this endpoint.
- Terminal delivery success rate is `accepted / (accepted + bounced)`. Deferred items are excluded until a terminal outcome is logged.
- Analytics are derived from persisted Postfix lifecycle events. They do not reconstruct events that occurred before event ingestion was enabled or beyond event retention.

### Prometheus metrics

The API exposes `/metrics` in Prometheus text format. It is protected by a bearer token generated by the one-shot `monitoring-secrets-init` service and persisted in the `mailcore_monitoring_secrets` Docker named volume. The API and Prometheus mount the same volume read-only at `/run/mailcore-secrets`. The same private volume stores the Grafana administrator password. This avoids missing host bind-source files on first startup.

Metrics include:

- HTTP request counts and request-duration histogram, grouped by method, normalized route and status.
- Node process uptime, resident memory and heap usage.
- PostgreSQL connection-pool counts and database transaction/block counters.
- Current Postfix total, active and deferred queue counts, plus bridge probe status.
- Mail lifecycle event counts for the last 24 hours.
- Event outbox pending/dead-letter counts and oldest pending age.

Metrics intentionally avoid mailbox addresses, usernames, IP addresses, message IDs and email bodies. Request route labels use registered route templates or a fixed `/unmatched` label to avoid path-based cardinality and personal-data leakage.

### Monitoring stack

- Prometheus `v3.5.0`, 30-day TSDB retention.
- Grafana `12.1.0`, provisioned Prometheus datasource and MailCore operations dashboard.
- Node Exporter `v1.9.1` for Linux host CPU, memory and filesystem metrics.
- Monitoring network is an internal Docker network.
- Prometheus and Grafana ports bind to `127.0.0.1` by default. Do not change the bind addresses to `0.0.0.0` on a public host. For remote access use VPN or an SSH tunnel (local port forwarding), for example:

```bash
ssh -L 3001:127.0.0.1:3001 -L 9090:127.0.0.1:9090 user@mail-host
```

Then open Grafana at `http://127.0.0.1:3001` and Prometheus at `http://127.0.0.1:9090` on the client computer.

## First-time setup and upgrades

1. Preserve the current `.env`, API `.env`, `secrets/runtime/`, TLS files and Docker volumes.
2. Run `./infrastructure/secrets/bootstrap.sh` to prepare the file-backed database, Redis and encryption credentials. The Compose `monitoring-secrets-init` service creates the Prometheus scrape token and Grafana admin password inside its named Docker volume before the API, Prometheus and Grafana start. It imports an existing `prometheus_scrape_token` or `grafana_admin_password` from `secrets/runtime/` when present, preserving credentials from an earlier Milestone 07 install. No host-side monitoring credential files are required for a fresh install.
3. Retrieve the initial Grafana administrator password on the server with:

```bash
docker compose exec -T grafana cat /run/mailcore-secrets/grafana_admin_password
```

4. Validate and start:

```bash
docker compose config -q
docker compose up --build -d
```

5. Verify:

```bash
./infrastructure/tests/milestone-07-runtime.sh
```

Never run `docker compose down -v` during an upgrade. The Prometheus and Grafana named volumes contain time-series history and Grafana state.

### Credential rotation notes

- The Prometheus scrape token and Grafana admin password are shared through the `mailcore_monitoring_secrets` named Docker volume. The init service creates them once, imports legacy host values when available, and preserves them across normal Compose upgrades. To rotate them, stop API, Prometheus and Grafana, remove only the `mailcore_monitoring_secrets` volume during a planned maintenance window, then recreate the stack so the init service generates new credentials. Do not remove the Prometheus TSDB or Grafana data volumes. Legacy host secret files are read-only only in the one-shot initializer for import; they are not mounted into the long-running API, Prometheus or Grafana services.
- Grafana reads the admin password secret when its database is initialized. Changing the secret file later does not reset an existing Grafana database; change the password in Grafana itself and maintain the secret as an operator recovery reference.

## Interpretation and limitations

- Postfix `status=sent` means the next SMTP/LMTP delivery endpoint accepted the recipient delivery (for external mail, this is accepted by the remote SMTP server). It does **not** guarantee final inbox placement, user visibility or absence of downstream filtering.
- Internal/external classification is based on whether the recipient domain exists in MailCore's configured `domains` table.
- Postfix queue metrics are a point-in-time sample from the queue bridge. When the bridge is unavailable, `mailcore_postfix_queue_probe_up` is `0`; queue gauges return zero and must not be interpreted as an empty queue unless the probe metric is `1`.
- Host metrics are designed for a Linux Docker host. Docker Desktop may expose the Linux VM's host metrics instead of the physical workstation's metrics.
- Node Exporter reads host `/proc`, `/sys` and root filesystem mounts read-only. It is reachable only from the internal monitoring network and is not published to a host port.
- This milestone does not add cAdvisor or mount the Docker socket. Container-level resource charts are deliberately omitted rather than granting a monitoring container privileged Docker API access.
- Prometheus and Grafana are pinned to explicit image versions. Review and update them through a tested upgrade, not an unpinned `latest` tag.
- The Prometheus endpoint returns `401` without the bearer token. Do not share the token or include its file in issue reports or source archives.

## Validation boundary

Static checks validate configuration wiring and protected endpoint behavior in source. The runtime script confirms Prometheus can scrape API/host targets, the queue metric is queryable and Grafana is healthy. It does not validate external Gmail/Microsoft inbox placement, backup recovery, or every host-specific filesystem collector.
